# Fix CI compile errors (523fb82 build)

## Root causes

1. **MainActivity.kt:15 — `Unresolved reference 'MeasureSpec'`**
   `android.view.MeasureSpec` is not a top-level class. It is nested inside
   `View`: `android.view.View$MeasureSpec`. The import line
   `import android.view.MeasureSpec` cannot resolve.

2. **ModelPack.kt:118 — `RandomAccessFile(FileDescriptor, String)` not available**
   Android's `java.io.RandomAccessFile` only has `(String, String)` and
   `(File, String)` constructors. The end-of-central-directory scan must use
   a different seekable read path.

## Fixes

### Fix 1 — MainActivity.kt (1 line)
- Change import at line 15 from:
  `import android.view.MeasureSpec`
  to:
  `import android.view.View.MeasureSpec`

  `MaxWidthLinearLayout.onMeasure` (uses `MeasureSpec.getSize`,
  `MeasureSpec.makeMeasureSpec`, `MeasureSpec.AT_MOST`) then resolves. No
  other changes needed in that class.

### Fix 2 — ModelPack.kt (`totalUncompressedSize`)
- Remove imports: `java.io.RandomAccessFile`.
- Add imports: `java.io.FileInputStream`, `java.nio.ByteBuffer`.
- Rewrite `totalUncompressedSize(fd: FileDescriptor)` to use
  `FileInputStream(fd)` (exists on Android, confirmed in android.jar) and its
  `channel` (`java.nio.channels.FileChannel`) for seeking:
  - `ch.size()` — file length
  - `ch.position(scanStart)` — seek to EOCD scan window (last 64 KB + 22)
  - read into a `ByteBuffer.allocate(scanLen)` via `ch.read(buf)` until full
  - find EOCD signature `0x06054b50`, read total-entry count (+10) and CD
    offset (+16)
  - `ch.position(cdOffset)`; for each entry read a 46-byte header
    (`ByteBuffer.allocate(46)`, loop `ch.read` until full), verify signature
    `0x02014b50`, sum uncompressed size (le32 at +24), then
    `ch.position(ch.position() + nameLen + extraLen + commentLen)` to advance.
  - Keep the existing `le16`/`le32` helpers and the `IOException("not a valid
    zip (no central directory)")` / `"corrupt zip central directory"` errors.
- `unzip`/`import`/progress reporting unchanged.
